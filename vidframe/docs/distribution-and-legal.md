# Распространение, подпись, лицензии, требования к устройству

## Каналы распространения

| Канал | Подходит | Замечания |
|---|---|---|
| **Sideload** (APK с GitHub Releases / сайта) | да | Подписывайте одним и тем же release-ключом. Публикуйте sha256 APK и отпечаток сертификата (`apksigner verify --print-certs`). |
| **Собственный F-Droid-репозиторий** | да, рекомендуется для обновлений | `fdroid init` → положите подписанные APK в `repo/` → `fdroid update -c` → выложите `repo/` на статический хостинг. Пользователь добавляет репозиторий в F-Droid / Droid-ify / Neo Store и получает обновления. Подпись APK — ваша. |
| **Основной репозиторий F-Droid** | возможно, с оговорками (ниже) | Нужна воспроизводимая сборка из исходников без проприетарных компонентов. |
| **Obtainium** | да | Обновления прямо из GitHub Releases. |
| **Google Play** | **нет** | Приложение, предназначенное для доступа к YouTube в обход официальных клиентов и с блокировщиком контента по умолчанию, нарушает правила Play о контенте третьих лиц, ToS YouTube и политику Developer Program («Interfering with other apps / services»). Такую сборку отклонят или удалят, а аккаунт разработчика могут заблокировать. Не публикуйте. |

## Подпись

* **Debug:** `./mach gradle fenix:assembleDebug` подписывает
  `~/.android/debug.keystore`. Такая сборка только для разработки: ключ
  общедоступен, `applicationId` = `io.github.vidframe.fenix.debug`.
* **Release:** `vidframe/scripts/sign.sh` (zipalign + `apksigner`, схемы
  v2+v3). Ключ RSA 4096, срок действия 10000 дней, хранится офлайн
  с резервной копией. Для ротации ключа используйте `apksigner rotate`
  (схема v3.1). Никогда не публикуйте сборку с debug-ключом под release
  `applicationId`.
* В CI держите keystore в секрете и передавайте пароли через
  `VIDFRAME_KS_PASS` / `VIDFRAME_KEY_PASS`.

## Лицензии

* **MPL-2.0** (Firefox, GeckoView, Fenix, Android Components и наши правки
  в этих файлах). Это файловый copyleft: изменённые MPL-файлы публикуются
  в исходниках (этот репозиторий), заголовки лицензий сохраняются. Новые
  файлы Vidframe тоже под MPL-2.0 (заголовок в каждом файле). Исходники
  должны быть доступны тем, кто получил бинарник: ссылка в README
  и в «О программе».
* **GPL-3.0** (uBlock Origin). Мы распространяем uBO в неизменном виде
  внутри APK. Это «aggregate» в терминах GPL-3.0 §5: остальной APK
  не становится GPL. Обязанности: указать лицензию и дать доступ
  к исходникам **той же версии**. Ссылка на тег
  `https://github.com/gorhill/uBlock/releases/tag/<UBO_VERSION>` из
  `ubo.lock` в README и в описании релиза. Не меняйте файлы XPI: это
  сломает подпись AMO.
* **Сторонние компоненты дерева Firefox** (about:license): лицензии уже
  собраны в `toolkit/content/license.html` и попадают в APK.
* **Товарные знаки.** «Firefox», логотип и `org.mozilla.*` использовать
  нельзя (Mozilla Trademark Policy). Поэтому используются неофициальный
  брендинг, свой `applicationId`, своя иконка и имя. Строки Fenix вида
  «Firefox» в глубине настроек (`app_name_firefox`, тексты о Mozilla) — это
  остаточный риск, вычищайте их по мере обнаружения. YouTube: имя, логотип
  и красно-белый трейд-дресс в названии, `applicationId`, иконке и
  метаданных не используются (`Vidframe`, `io.github.vidframe.app`,
  нейтральная иконка). Упоминание «YouTube» допустимо только
  описательно (nominative use) и вместе с дисклеймером.
* **Сторонний загрузчик (savefrom.net).** Кнопка «Скачать» передаёт ссылку на видео стороннему сервису.
  Скачивание роликов нарушает Условия использования YouTube и может нарушать авторские права, если у
  пользователя нет прав на видео; часть таких сервисов показывает агрессивную рекламу. Поэтому сервис
  открывается только во внешнем браузере (в клиент он не попадает), а сборка с `-Pvidframe.downloader=`
  (пусто) эту функцию отключает. Для публикации в каталогах (F-Droid и др.) решите, оставлять ли её,
  и не рекламируйте приложение как «загрузчик видео».
* **Маркетинг.** Не пишите «без рекламы», «обход рекламы», «бесплатный
  Premium». Корректная формулировка: «включает универсальный блокировщик
  контента uBlock Origin».

## F-Droid: что меняется

Требования основного репозитория F-Droid: всё собирается из исходников на
их сервере, нет проприетарных библиотек и нет скачиваемых бинарников.

| Компонент | Проблема | Решение |
|---|---|---|
| Google Play Services / Firebase Messaging (push в Fenix) | Проприетарные | В Fenix они изолированы (`lib-push-firebase`). Их нужно исключить из сборки: так делают IronFox и Mull, см. их `prebuild` (замена зависимостей на заглушки). |
| Glean / телеметрия | Свободный код, но AntiFeature `Tracking` | Выключена по умолчанию. F-Droid может всё равно потребовать удаления и пометить приложение антифичей. |
| Предсобранные toolchain (clang, rust, NDK из `mach bootstrap`) | F-Droid использует свой NDK и rustup | Сборочный рецепт должен ставить NDK r30 из F-Droid и свой rust; `--with-ccache` и `--enable-bootstrap` отключить. |
| `ublock_origin.xpi` с AMO | Скачиваемый бинарник | **Вариант F-Droid:** собирать uBO из исходников (`gorhill/uBlock`, `tools/make-firefox.sh`, тег из `ubo.lock`) и ставить его как **встроенное** расширение через `installBuiltInWebExtension`, потому что неподписанный XPI release-Gecko не установит как обычный аддон. Минус: код uBO обновляется только вместе с APK. Фильтры по-прежнему обновляются сами. |
| `NonFreeNet` | Приложение работает только с несвободным сервисом | F-Droid ставит антифичу `NonFreeNet`. Это допустимо (как у NewPipe). |
| Время сборки и память | Firefox на сервере F-Droid собирается часами | Принимается только с рецептом, как у Fennec F-Droid. Будьте готовы сопровождать `metadata/*.yml` сами. |

Черновик метаданных: `vidframe/fdroid/io.github.vidframe.app.yml`. Он
подходит и для собственного репозитория (там же можно без сборки
из исходников).

**Практический вывод:** основной канал — собственный F-Droid-репозиторий
с подписанными вами APK (AMO-подписанный uBO с автообновлением).
Основной репозиторий F-Droid — отдельный «libre»-флейвор (без FCM,
uBO из исходников как встроенный), если вы готовы его поддерживать.

## Минимальные требования к устройству

| Параметр | Минимум | Рекомендуется | Откуда |
|---|---|---|---|
| Android | 8.0 (API 26) | 11+ | `min_sdk_version="26"` в `build/moz.configure/android-sdk.configure` |
| ABI | armeabi-v7a или arm64-v8a | arm64-v8a | сплиты в `fenix/app/build.gradle`; x86_64 только для эмулятора |
| RAM | 2 ГБ | 4 ГБ+ | Gecko + процесс расширений + видео 1080p |
| Хранилище | ~300 МБ после установки | 1 ГБ | APK ~100 МБ + профиль + кэш видео |
| WebView | не нужен | — | движок встроен |
| Google Play Services | не нужны | — | push не используется |

Проверка подключённого устройства:

```bash
vidframe/scripts/check-device.sh
```

Вручную:

```bash
adb shell getprop ro.build.version.sdk
```

```bash
adb shell getprop ro.product.cpu.abilist
```

```bash
adb shell cat /proc/meminfo
```

Если в `abilist` есть только `armeabi-v7a`, даже на 64-битном SoC
(32-битная прошивка), ставьте armeabi-v7a APK.
