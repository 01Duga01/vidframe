# G. Чек-лист тестирования перед релизом

Каждый пункт проверяется на **чистой установке** и на **обновлении поверх
предыдущего релиза**. Матрица устройств:

| # | ABI | Android | Пример | Зачем |
|---|---|---|---|---|
| 1 | arm64-v8a | 15 / 16 (API 35–36) | Pixel 7–9 | основная платформа, predictive back |
| 2 | arm64-v8a | 12–13 (API 31–33) | Samsung A5x (One UI) | вендорская оболочка, агрессивный kill фона, app links |
| 3 | arm64-v8a | 8.0 / 9 (API 26–28) | любой 2 ГБ RAM | минимальный API, мало памяти |
| 4 | armeabi-v7a | 8–11 | бюджетный 32-битный (или arm64-устройство с 32-битной ОС) | второй ABI |
| 5 | x86_64 | эмулятор API 34 | AVD | только смоук; не публикуется |

Перед началом:

```bash
vidframe/scripts/check-device.sh
```

```bash
adb logcat -c
```

```bash
adb logcat -s VidframeNav VidframeDoH VidframeUbo Vidframe GeckoConsole
```

## Запуск и оболочка

- [ ] Иконка «Vidframe» с нейтральной иконкой. Нигде нет логотипов
      Firefox/YouTube, в том числе в «Недавних», уведомлениях и на сплэше.
- [ ] Первый запуск: короткий индикатор, пока ставится uBO, затем сразу
      m.youtube.com, и первая же страница уже фильтруется uBO.
- [ ] Ярлык «Настройки» → «назад» возвращает на m.youtube.com, а не на
      домашний экран Fenix; адресной строки и поиска Fenix нигде нет.
- [ ] В выборе виджетов лаунчера нет поисковых виджетов Vidframe.
- [ ] Первый запуск сразу открывает m.youtube.com: нет onboarding, Terms of
      Use, домашнего экрана, адресной строки и вкладок.
- [ ] Повторный запуск из иконки возвращает в ту же сессию (видео на паузе,
      а не новая загрузка).
- [ ] Долгое нажатие на иконку показывает «Настройки», «Блокировщик» и
      «История», и каждый ярлык открывает свой экран.
- [ ] «Настройки» → «О программе» показывает дисклеймер независимости.
- [ ] Vidframe не предлагается как браузер по умолчанию и не появляется
      в chooser для `https://example.com`:
      ```bash
      adb shell cmd package query-activities -a android.intent.action.VIEW -c android.intent.category.BROWSABLE -d https://example.com
      ```

## Плеер

- [ ] Воспроизведение 360p, 720p, 1080p; ручная смена качества.
- [ ] Перемотка, двойной тап ±10 с, скорость 0.25–2×.
- [ ] Полноэкранный режим: вход и выход кнопкой, жестом, кнопкой «назад».
- [ ] **Поворот экрана** в плеере и в ленте: видео не перезапускается,
      позиция сохраняется (у `ExternalAppBrowserActivity` есть
      `configChanges=orientation|screenSize`).
- [ ] Автовоспроизведение следующего видео (если включено на сайте).
- [ ] Shorts: вертикальная прокрутка, звук, пауза.
- [ ] **Субтитры:** включение, выбор языка, автоперевод, размер.
- [ ] **Трансляции (live):** запуск, DVR-перемотка назад, «к эфиру»; чат
      открывается и прокручивается.
- [ ] Видео 18+ и видео с ограничением по региону: корректная заглушка
      сайта, не белый экран.
- [ ] Звук через Bluetooth-гарнитуру; кнопки play/pause на гарнитуре.

## Фон и медиа-сессия

- [ ] Сворачивание приложения: поведение совпадает с Firefox for Android
      (медиа-уведомление Fenix, воспроизведение продолжается или
      ставится на паузу так же, как на этой версии Fenix).
- [ ] Медиа-уведомление: play/pause, закрытие, иконка без бренда Firefox.
- [ ] Блокировка экрана во время воспроизведения.
- [ ] Picture-in-Picture (кнопка «Домой» в полноэкранном режиме).
- [ ] Через 30+ минут в фоне (Samsung, Xiaomi) возврат без падения;
      если ОС убила процесс, сессия восстанавливается.

## Кнопка «назад» (аппаратная и жест)

- [ ] Лента → видео → «назад» возвращает в ленту, а не закрывает приложение.
- [ ] Поиск → результаты → видео → «назад» ×2 возвращает к результатам и
      строке поиска.
- [ ] Полноэкранный режим → «назад» выходит из полного экрана.
- [ ] На корне ленты «назад» закрывает activity; повторный запуск
      восстанавливает сессию.
- [ ] Android 14+: predictive back показывает анимацию, без двойного
      срабатывания.
- [ ] Страница-заглушка allowlist → «назад» возвращает на исходную
      страницу.

## Поиск и логин

- [ ] Поиск внутри сайта: ввод, подсказки, голосовой ввод (если сайт его
      предлагает); результаты открываются.
- [ ] Вход в аккаунт Google: `accounts.google.com`, 2FA (код, push,
      passkey, если поддерживается Gecko), капча `www.google.com/recaptcha`.
- [ ] После входа виден аватар, подписки и история просмотров на сайте.
- [ ] Переключение аккаунтов, выход.
- [ ] Диалог согласия на cookies (`consent.youtube.com` / `consent.google.com`)
      на чистом профиле из ЕС-региона (VPN) принимается и отклоняется.
- [ ] Локальная история: ярлык «История» показывает посещённые видео;
      синхронизации нет и вход в аккаунт Mozilla не предлагается.

## Allowlist

- [ ] Ссылка из описания видео на внешний сайт показывает заглушку
      (`strict`), а в `warn` ещё и кнопку «Открыть во внешнем браузере»,
      которая открывает chooser **без** Vidframe.
- [ ] `vidframe-external://open?u=https://example.com` без жеста (через
      `adb shell am start`) **не** открывает chooser.
- [ ] Ссылка на `www.google.com/search?q=test` блокируется.
- [ ] Схемы `intent://`, `vnd.youtube:`, `market://` блокируются, нативное
      приложение YouTube (если установлено) не запускается.
- [ ] Ссылка `https://youtu.be/<id>` из мессенджера открывается в
      Vidframe (после включения «Поддерживаемые ссылки» на Android 12+).
- [ ] Встроенные iframe сторонних доменов на m.youtube.com молча
      отклоняются (`VidframeNav: Blocked navigation (subframe=true)`).

## uBlock Origin на m.youtube.com

- [ ] Чистая установка: uBO виден в «Блокировщик» и включён, без
      диалога разрешений; разрешён в приватных вкладках.
      `VidframeUbo: Installed uBlock0@raymondhill.net <version>`.
- [ ] Версия uBO совпадает с `vidframe/config/ubo.lock`.
- [ ] uBO → Панель управления открывается (`moz-extension://`),
      настройки сохраняются после перезапуска.
- [ ] Списки фильтров: «Обновить сейчас» успешно, даты обновления свежие.
- [ ] Обновление uBO с AMO: в debug-сборке «Дополнения» → uBO →
      «Проверить обновления», или дождитесь задачи `DefaultAddonUpdater`.
- [ ] Удаление uBO пользователем: после перезапуска **не**
      переустанавливается.
- [ ] На главной, в поиске, на странице видео и в Shorts нет поломок
      вёрстки; плеер стартует без «чёрного экрана».
- [ ] Нет antiblock-попапа; если он есть, обновить списки и проверить
      issues uAssets (см. F).
- [ ] Селекторы `vidframe-ui` всё ещё актуальны: плашки «Открыть
      в приложении» не видно. Если имя элемента изменилось, обновите
      `m-youtube.css` и `css/userContent.css`.

## DoH

- [ ] Debug-сборка: `about:networking#dns` показывает TRR = true для
      `*.youtube.com` и `*.googlevideo.com`.
- [ ] `verify-doh.sh` с выключенным Private DNS: нет content-host'ов
      в открытом DNS.
- [ ] Failover: заблокируйте `dns.adguard-dns.com` на роутере и смените
      сеть (Wi-Fi ↔ мобильная). В логе
      `VidframeDoH: Switching DoH resolver to https://unfiltered.adguard-dns.com/dns-query`,
      видео грузятся.
- [ ] Все endpoint'ы недоступны: страницы не грузятся (TRR-only), без
      отката на системный DNS.
- [ ] Обновление поверх старой версии: DoH-режим = Max, пункт DoH
      в настройках скрыт.

## Телеметрия и сеть

- [ ] Настройки → Сбор данных: всё выключено на чистой установке.
- [ ] mitmproxy или лог роутера за 10 минут использования: нет
      запросов к `incoming.telemetry.mozilla.org`, `*.glean*`,
      `firefox.settings.services.mozilla.com` кроме blocklist/remote settings,
      `contile.services.mozilla.com`, Pocket.
