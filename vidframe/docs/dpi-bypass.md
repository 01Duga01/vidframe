# Обход DPI внутри приложения

## Почему не «нативный Zapret2»

Zapret2 (`nfqws2`) перехватывает пакеты всей системы через `iptables`/`nftables` и очередь NFQUEUE.
На Android для этого нужен **root**, а обычное приложение получить его не может. Без root остаются
два пути: системный `VpnService` (как в ByeDPI for Android: в статус-баре значок VPN, весь трафик
устройства идёт через приложение) или обработка только **собственных** соединений приложения.

Vidframe использует второй путь. Тот же класс техник, что у `tpws` из zapret и у ByeDPI,
реализован прямо в клиенте:

* без root и без VPN, на других приложениях это не сказывается;
* без внешних бинарников и дополнительных лицензий (код MPL-2.0, `org.mozilla.fenix.vidframe.dpi`);
* работает и в artifact-сборке, потому что это Kotlin, а не C++ в Gecko.

Пакетные трюки, которым нужны сырые сокеты (fake-пакеты с малым TTL, disorder, «badsum»), без root
недоступны. Из арсенала zapret2 доступна только TCP-часть.

## Как это работает

```
GeckoView ──SOCKS5 (IP-адреса)──▶ DpiBypassProxy 127.0.0.1:<порт> ──TCP──▶ сервер
                                   │ первая TLS-запись соединения:
                                   │   ClientHello → 2 TLS-записи (разрез внутри SNI)
                                   │   → 3 TCP-сегмента (после 1-го байта и внутри SNI)
                                   └ остальное — без изменений, в обе стороны
```

* `TlsDesync` разбирает ClientHello, находит SNI и режет его (`--tlsrec` + `--split` в терминах
  tpws/ByeDPI). Сервер собирает handshake из нескольких записей (RFC 8446 §5.1). Проверено:
  OpenSSL (TLS 1.3) с таким ClientHello завершает handshake и видит правильный SNI.
* `DpiBypassProxy` — SOCKS5 (только CONNECT, без авторизации) на `127.0.0.1`, порт случайный,
  поток на направление, `TCP_NODELAY`. Разрезается только порт 443.
* `DpiBypass` при старте настраивает Gecko на default-ветке префов:
  `network.proxy.type=1`, `network.proxy.socks=127.0.0.1`, `socks_port`, `socks_version=5`,
  `network.proxy.socks5_remote_dns=false` (Gecko резолвит через DoH и передаёт IP, иначе имена
  уходили бы в системный DNS, который в РФ может подменять ответы),
  `network.http.http3.enable=false` (QUIC идёт по UDP мимо SOCKS, и разрез к нему неприменим).
* Ресурсы ограничены, потому что лента Shorts открывает и бросает много соединений: два потока со
  стеком 256 КБ и буферы по 16 КБ на соединение; соединение закрывается целиком, как только любая
  сторона его завершила; одновременно не больше 384 соединений; ни одно исключение не выходит из
  рабочего потока (на Android это уронило бы всё приложение).
* Предварительные подключения (`speculativeConnect`) делаются только после того, как Gecko
  переключён на прокси.

## Включение

| `-Pvidframe.dpiBypass=` | Поведение |
|---|---|
| `auto` (по умолчанию) | Включается, если страна мобильной сети, SIM или региона системы — `RU` |
| `on` | Всегда |
| `off` | Никогда |

Проверка: `adb logcat -s VidframeDpi` → `DPI bypass active on 127.0.0.1:<порт>`.

## Ограничения

* **Работает не у всех провайдеров.** ТСПУ разных операторов ведут себя по-разному. Если
  разреза SNI мало (оператор собирает TCP-поток или режет по IP), без fake-пакетов (root) или
  внешнего туннеля обойти блокировку не получится. Стратегию можно менять в
  `TlsDesync.Strategy` (`splitRecord`, `splitSegments`).
* Обход действует только на соединения Vidframe, другие приложения не затрагиваются.
* Небольшая задержка на каждое новое TLS-соединение (два лишних сегмента) и один локальный
  переход через loopback. На скорость видео это не влияет.
* Без HTTP/3 первые соединения на некоторых сетях чуть медленнее; в РФ QUIC к Google часто и
  так ограничен.

## Юридическая оговорка

В России действуют ограничения на распространение и популяризацию средств обхода блокировок.
Публикация сборки с включённым обходом, особенно с рекламой этой функции, может нарушать местное
законодательство, а приложение может быть заблокировано. Решение о распространении и о
формулировках в описании принимает и за него отвечает тот, кто публикует сборку. Сборка с
`-Pvidframe.dpiBypass=off` не содержит активного обхода.
